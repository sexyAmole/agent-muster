# 渠道记录口径

使用 [渠道记录表](./channels.csv)，每个渠道、版本和统计周期一行。发布前填写来源、唯一渠道标识、投放链接和负责人；发布后补齐结果。当前没有采集数据，空白表示未知，只有实际确认没有事件时才填 0。

- 来源：具体到平台和发布位置，例如某社区的一篇帖子。投放链接可带 `utm_source`、`utm_medium`、`utm_campaign`，不要把个人信息放进参数。
- 下载量：填写统计周期内的安装包下载次数及取数时间。GitHub Release 的资源下载次数只能说明整体下载，不能直接归因某一渠道；没有渠道级统计时留空并注明原因。重复下载不等于独立用户。
- 首次任务人数：通过用户自愿反馈或访谈确认，首次发送任务并收到 Agent 结果的去重人数，注明取数方式。下载和点击不能计为完成首次任务。
- 问题反馈：记录具体阻塞点，附脱敏后的 Issue 或反馈链接；不要保存凭证、聊天原文或本地目录。
- 是否留存：填「待观察」「是」「否」或「未知」。首次任务后第 7 日再次执行任务计为留存；渠道内至少一人留存填「是」，均完成观察且无人留存填「否」，同时记录第 7 日留存人数。无法追踪时填「未知」，不要推断为未留存。

这是一张人工运营记录表，官网当前没有自动统计或跨端用户识别。每周按相同口径回填；渠道归因不清的数据只记录在「来源＝整体」的行，避免重复计数。渠道转化率只在分子、分母来自同一可归因人群时计算。
