# Agent Muster

[English](./README.md) | 简体中文

在本地浏览器中管理多个 AI 编码 Agent、项目和对话，也可以通过钉钉或飞书机器人向 Agent 发送任务并接收回复。

## 功能

- 自动检测本机已安装的 Codex、Claude Code、Pi 和 Kimi CLI。
- 按项目管理对话，支持单窗、双窗和四窗布局，同时查看和继续不同任务。
- 选择 Agent 和模型，实时查看回复、工具调用、执行状态及可用的 Token 用量。
- 保存项目和对话记录，支持继续对话和停止正在运行的任务。
- 通过独立的 IM 集成页面，将钉钉和飞书应用接入本地 Agent。

## 环境要求

- Node.js **22.19.0 或更高版本**。
- 要执行任务，需要先安装并配置至少一个支持的 Agent CLI，并确保其命令在 `PATH` 中可用。
- Agent 的登录、模型权限和费用由对应服务管理。

| Agent | 检测的命令 |
| --- | --- |
| Codex | `codex` |
| Claude Code | `claude` |
| Pi | `pi` |
| Kimi CLI | `kimi` |

## 快速开始

无需全局安装，直接启动：

```bash
npx agent-muster
```

启动后会自动打开浏览器，默认地址为：

```text
http://127.0.0.1:17321
```

也可以全局安装：

```bash
npm install -g agent-muster
agent-muster
```

保持启动终端运行，按 `Ctrl+C` 停止服务。当前 Web 界面使用中文标签。

## 命令

| 命令 | 说明 |
| --- | --- |
| `agent-muster` | 启动 Web 界面并打开浏览器 |
| `agent-muster web` | 显式启动 Web 界面 |
| `agent-muster web --no-open` | 启动服务，不自动打开浏览器 |
| `agent-muster web --port 18000` | 指定监听端口 |
| `agent-muster agents` | 列出 Agent 及安装状态 |
| `agent-muster sessions` | 列出已保存的对话 |
| `agent-muster update` | 检查并更新全局安装到最新版本 |

端口和浏览器选项可以组合使用：

```bash
npx agent-muster web --port 18000 --no-open
```

服务仅监听本机地址 `127.0.0.1`，使用上述自定义端口时，请访问 `http://127.0.0.1:18000`。

## 创建第一个任务

1. 启动 Agent Muster，在 Web 界面点击「添加项目」，选择一个本地项目目录。
2. 在该项目下点击「创建对话」，选择已安装的 Agent 和模型。
3. 输入任务并发送，例如：`检查这个项目的启动流程，说明如何运行。`
4. 在对话窗口查看回复、工具调用和执行状态，继续发送消息完成任务。

Agent 在选中的项目目录中执行任务。模型列表取决于对应 CLI 的配置与可用权限。继续对话需要 Agent 已创建可恢复的会话。

## IM 集成

在侧边栏打开「IM 集成」，选择「钉钉」或「飞书」。每个应用分别绑定项目和 Agent。

| 能力 | 钉钉 | 飞书 |
| --- | --- | --- |
| 创建应用 | 使用钉钉扫码创建 | 使用飞书扫码创建 |
| 消息监听 | 钉钉 Stream SDK | 飞书 SDK WebSocket 长连接 |
| 接收消息 | 文本、图片和图文消息 | 文本消息 |
| 对话场景 | 单聊、群聊中提及机器人 | 单聊、群聊中提及机器人 |
| 消息回复 | Agent 自动回复、Web 界面主动发送 | Agent 自动回复、Web 界面主动发送 |
| 应用管理 | 绑定项目和 Agent、同步名称和图标、删除本地接入 | 绑定项目和 Agent、同步名称和图标、查看连接状态、删除本地接入 |

### 扫码创建与绑定应用

1. 先在 Agent Muster 中添加项目，确认目标 Agent 已安装并配置完成。
2. 打开「IM 集成」，选择平台，点击「扫码创建应用」。
3. 使用对应平台的手机应用扫描二维码，按授权页面提示完成应用创建和授权。二维码过期后可重新获取。
4. 为创建的应用选择项目和 Agent，点击「一键同步」可更新平台上的名称和图标。
5. 向机器人发送单聊消息，或将机器人加入群聊并提及它发送任务。使用飞书时，确认应用状态显示「消息监听已连接」。

接入期间需要保持 Agent Muster 运行，并能连接对应平台。本地服务通过 SDK 建立连接接收消息，无需提供公网 Webhook 地址。

### 接收任务与自动回复

收到消息后，Agent Muster 会在绑定项目中调用选定的 Agent，任务结束后将结果发送回原 IM 对话。

同一 IM 对话会继续使用已有的本地 Agent 会话，消息按顺序处理。修改应用绑定的项目或 Agent 会清空 IM 对话映射，下一条消息将创建新的本地对话。

钉钉图片输入支持 Codex、Claude Code 和 Pi，当前 Kimi CLI 接入不支持图片输入。飞书接入目前只处理文本消息。

### 在 Web 界面主动发送消息

打开由 IM 创建的本地对话，在输入框旁选择发送方式：

- 「发送到钉钉」或「发送到飞书」：以应用身份将输入的文本直接发送到关联的 IM 对话，不运行 Agent；发送记录保存在本地对话中。
- 「交给 Agent」：继续本地 Agent 任务，此模式不会将执行结果自动发送到 IM。

主动发送需要已有的 IM 对话映射。飞书发送较长的回复时会分成多条文本消息。

### 删除接入

点击应用条目中的「删除」，可移除本地接入并停止接收该应用的消息。已有对话记录会保留，钉钉或飞书平台中的应用不会被删除。

## 本地数据

项目、对话和 IM 接入配置保存在用户主目录下的 `.agent-muster` 中，重新启动后会读取已有记录。钉钉和飞书应用凭证分别保存在 `dingtalk-apps.json` 和 `feishu-apps.json` 中，请妥善保管这些文件。

## 常见问题

### Agent 显示未安装

在启动 Agent Muster 的终端中运行对应命令，确认 CLI 已安装且可以正常执行。安装或调整 `PATH` 后重新启动 Agent Muster。

### 默认端口被占用

通过 `--port` 指定其他端口：

```bash
npx agent-muster web --port 18000
```

### IM 机器人没有回复

确认本地服务仍在运行，已完成平台授权，应用已绑定项目和可用的 Agent。群聊中需要提及机器人；使用飞书时，检查连接状态并发送文本消息。可以在 Web 对话日志和启动终端中查看任务状态与错误信息。

### Web 界面无法主动发送消息

先从 IM 向机器人发送一条消息，再打开由此创建的本地对话。确认应用接入仍存在，项目和 Agent 绑定未被修改，并选择「发送到钉钉」或「发送到飞书」后发送。

## 更新

启动 Web 服务时会在后台检查新版本，并在终端显示更新提示。

全局安装的用户可以运行：

```bash
agent-muster update
```

命令会检查最新版本，已有新版本时通过 npm 更新全局安装。更新完成后重新启动服务即可生效，也可以手动更新：

```bash
npm install -g agent-muster@latest
```

使用 `npx` 时，可以明确指定最新发布版本：

```bash
npx agent-muster@latest
```
