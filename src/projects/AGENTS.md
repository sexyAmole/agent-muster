# 项目模块

## 模块约定

- 项目注册使用已存在目录的绝对路径；`storage.ts` 统一生成项目数据目录，保持与会话存储一致。
- 项目名称、排序和路径写入 `project.json`，注册表写入串行化并通过临时文件替换，避免并发操作覆盖元数据。
- 文件访问接收项目内相对路径，同时核对解析路径和真实路径，阻止 `..` 及符号链接越过项目边界。
- 文件预览保留大小、二进制和编码检查；搜索保留排除目录及结果上限。
- Git 命令使用参数数组、literal pathspec 和 `--` 分隔路径，保留超时及输出大小限制。
- 分支切换只接受当前分支列表中的目标；远程分支核对已有本地分支的跟踪关系，切换失败直接报告 Git 错误。
- 删除项目会删除 Muster 项目数据；会话、IM 绑定和终端的清理由 HTTP 项目路由协调，不在注册表内隐式跨模块操作。

## Structure

- `registry.ts`：项目加载、旧数据迁移、添加、删除、改名与排序。
- `storage.ts`：按规范化项目路径的 SHA-256 计算存储目录。
- `files.ts`：目录浏览、文件预览和文件搜索。
- `git.ts`：Git 状态、差异、元数据目录查询及分支切换。

## Dependencies

- 依赖 Node.js 文件系统、路径、哈希和子进程 API，以及本机 Git CLI。
- 文件和 Git 返回结构依赖 `../types.ts`，`../sessions/store.ts` 复用项目目录计算。
- 由 HTTP 路由、运行时及 IM 命令调用，保持项目功能与平台 SDK、HTTP 请求对象分离。
